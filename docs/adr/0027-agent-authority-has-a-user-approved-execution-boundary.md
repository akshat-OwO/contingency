# Agent authority has a user-approved Execution Boundary

> [ADR 0052](./0052-workspace-boundary-decisions-resume-stored-attempts.md) adds direct Workspace decisions and resumption of stored, undispatched attempts. Replaying an attempt returns its receipt. A new irreversible attempt still needs fresh Confirmation.

> [ADR 0044](./0044-agents-own-flow-skill-execution.md) supersedes active-Step authority for task Runs. The user's requested task authorizes exploration and recovery; unrelated tasks require user authorization. Domain Scope admits hosts declared by user-requested Flow Skills, including later requests, or the starting host when no skill supplies a scope. Per-attempt Confirmation, intervention for unrelated hosts, and exclusive Takeover remain. The text below records the historical step contract, which the runtime retains during integration.

An external agent may generate and execute its own plan, but only inside an **Execution Boundary** approved by the user. Each Agent Flow declares a **Domain Scope** proposed from Teaching and explicitly approved by the user. A new domain pauses the Run. The user also marks irreversible or high-impact objectives as **Confirmation Steps**. Confirmation authorizes one specific irreversible browser action attempt, not the whole Step or Run; retrying it requires fresh confirmation because a timed-out submission may already have succeeded. An action belongs to the active Agent Step by default, and the agent may describe that objective in its own words. The agent must explicitly classify an objective as new when it starts work outside the approved Agent Steps, which pauses under the same rule. Exact or fuzzy natural-language matching cannot reliably distinguish a paraphrase from a new objective, and omission already binds an action to the active Step, so objective text is not an authority signal. Navigation to a host already inside the approved Domain Scope is never an unknown objective because Domain Scope already decides where the session may go. This trusts the agent's plan without treating its prompt as a security boundary.

During **Takeover**, browser control is exclusive: Contingency disables agent action tools, continues recording, represents sensitive inputs as Variable references, and resumes agent actions only after the user returns control. Concurrent input was rejected because it makes the Demonstration and Run ordering unreliable; pausing recording was rejected because it hides the interval where the agent needed help.

[ADR 0037](0037-pending-decisions-relay-user-consent-over-mcp.md) partially supersedes the original direct-control rule for Verification Run authorization, Agent Flow approval, and releasing a paused Execution Boundary. Those choices now use server-issued Pending Decisions relayed through the MCP conversation. What the Boundary pauses, what a grant covers, and the Takeover rules are unchanged: only where the user answers moved.
