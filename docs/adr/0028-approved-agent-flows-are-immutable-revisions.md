# Approved Agent Flows are immutable revisions

Editing an **Approved Agent Flow** creates a draft **Agent Flow Revision** instead of changing the approved revision in place. The approved revision remains available while the draft is edited, verified, and presented for user approval. The agent may request verification and approval, but only direct user controls in Agent View may authorize one Verification Run or approve its resulting revision. That authorization applies to one exact draft; a post-failure edit requires another authorization. Catalog deletion archives by default, and permanent deletion requires explicit user confirmation. This keeps a failed agent edit, incomplete Teaching session, or self-approving agent from destroying or replacing the company's last usable sanity procedure.

Catalog writes use optimistic concurrency: each draft mutation names the revision it started from. If another process changed the draft or approved head, the write returns a conflict and the agent must reread before proposing another revision. Contingency does not automatically merge ordered Agent Steps, Domain Scope, Variables, Confirmation Steps, or evidence references.
