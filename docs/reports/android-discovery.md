# Android discovery and element bounds

Issue #485 adds optional device-pixel rectangles to Android observation nodes and two read-only Workspace RPCs.

`android.devices.list` returns connected devices with serial, emulator or physical kind, model, API level and ADB state. Connected devices also include fingerprint and emulator AVD name so the caller can construct an explicit selection. Unavailable metadata is null for unauthorized or offline devices. Listing never selects hardware.

`android.apps.list` takes the same explicit local device selection as Android Workspace. ADR 0058 defines selection as hardware authorization. The service requires ADB authorization, owner user 0 and matching serial, fingerprint, API level, device kind and model or AVD. It rechecks identity after reading the inventory. It returns launchable packages with application label, version code, version name and a launcher activity. This follows the current API 36 selection contract; discovering another API level does not qualify it for execution.

App metadata comes from the installed APK's manifest and resource table. ADB streams those entries through `unzip -p`; Contingency packages them in an owned temporary host archive and reads them with Android SDK `aapt2`. SDK build-tools are required. Discovery never installs a helper, launches an app, adds a forward or extracts files onto the device. Temporary archives are removed on success, failure and interruption. Large resource tables can still make app discovery slow over USB.

Each optional `bounds` field contains `x`, `y`, `width` and `height` in device pixels. The containing Workspace observation supplies its ID and display width and height. Backend rectangles must contain finite coordinates and nonnegative dimensions. Missing rectangles remain absent. This adds no coordinate dispatch capability or Workspace UI.

Verification uses the [Android discovery recipe](../../.cursor/skills/verify-contingency/features/workspace.md#android-discovery-and-element-bounds). Deterministic tests cover optional and invalid bounds, Workspace propagation, unauthorized and offline devices, device identity drift before and after inventory, empty inventories and malformed app metadata. Live RPC receipts compare installed-package, foreground-window and ADB-forward hashes before and after discovery. Bounds receipts use the production runtime factory and Workspace observation codec; they are separate from a complete Workspace Teaching journey.

Live proof passed on Pixel_9 API 36 and the authorized Nothing Phone 3a API 36. The final production RPC returned 22 launchable apps on the emulator and 88 on the phone. Both inventories refused a changed fingerprint, preserved package, foreground-window and forwarding hashes, and removed temporary metadata archives. Captures retained bounds for 173 emulator nodes at 1080 × 2424 and 49 phone nodes at 1080 × 2392. Sample rectangles were checked against temporary screenshots, which were deleted after inspection. The [sanitized receipts](./android-discovery-evidence.json) contain counts, display dimensions, sample rectangles and state hashes. ADB `unauthorized` refusal is covered by deterministic tests; the live refusal uses a mismatched selected identity without revoking the phone's host authorization.

Validation passed with 63 tests across nine affected Android and RPC files, CLI and web type checks, repository quality checks and a forced production CLI build. Cleanup removed the helper installed only for the owned emulator, stopped that emulator, and closed both isolated server/browser instances. The owned PIDs and ports were checked after cleanup. The phone's pre-existing helper remains installed, with no helper process or ADB forwards left running.
