# iOS Workspace Teaching and Runs

This branch implements ADR 0067 on the internal iOS Workspace. The complete Support Matrix remains unproven. `CONTINGENCY_IOS_WORKSPACE_INTERNAL=1` exposes the internal Workspace only; public device MCP still returns `ios_support_matrix_unproven`.

## Runtime behavior

ADR 0067 permits all semantic controls on the Session Simulator, including system alerts, Settings, other apps, and untaught controls. System alerts and untaught controls have live proof; Settings and other-app observation refuse with `foreign_app_foreground` under the documented iOS limit below. Simulator identity, current observation, covered targets, controller authority, capture integrity, and lifecycle checks still apply. The framebuffer helper, stream, fresh Session Simulator preparation, recorded-resource scavenging, and scoped cleanup are preserved.

Discovery lists simulators only. A physical selection returns `physical_device_unsupported` before any device command. The selected template supplies device type, runtime, and app build and is never booted or changed.

Variables are ordinary text. Stock agent-device enters every value through the shared `native-app-fill.ts` path. SDK readback success records `confirmed`; unavailable readback records `entered` and `unconfirmed`. The shared native runtime always makes secure-field fills unconfirmed. Runtime evidence carries values; saved skills carry only Variable names. The login fixture teaches a readable Login name and a secure `{{PASSWORD}}` fill, followed by **Sign in privately**, **Open account**, and **Return to account**.

Both Android and iOS use `native-app-confirmation.ts` and the existing Execution Boundary service. An agent action marked `irreversible: true` creates a Pending Decision before dispatch. Workspace displays the exact action. Approval consumes a grant for that stored attempt, refusal dispatches nothing, and every retry requires a fresh decision. Operation receipts prevent duplicate dispatch. This shared-layer change is kept on this branch.

## Foreign-app observation limit and recovery

The [P2 review finding](https://github.com/akshat-OwO/contingency/pull/562#discussion_r4409636020) prompted a documented iOS limit. The pinned SDK cannot observe whichever app is in front. Every snapshot now passes `observeOnly: true`; it must never activate the Target App. `OBSERVATION_UNAVAILABLE` becomes `foreign_app_foreground`, with an explicit `return-to-target-app` recovery. Teaching pauses without ending its recording, and Dry Runs and Runs use the same observation path. Workspace exposes **Return to Target App**, and the shared device command schema and Workspace RPC expose the command. Public iOS MCP remains gated.

Recovery validates the existing session's simulator binding and calls agent-device `apps.open` for the session's Target App with `relaunch: false`, the same UDID, and the same SDK session. A fresh observe-only capture resumes the journey. This recovery keeps the healthy framebuffer source and Teaching interval; transport recovery alone restarts the stream. It does not recreate the simulator or reinstall the app.

All SDK references are relative to `node_modules/.store/agent-device@0.21.25/node_modules/agent-device/`:

- `dist/src/client-types.d.ts:224-231` defines `AppOpenOptions.relaunch`. `dist/src/session2.js`, `bs`, passes that flag to `openApplication`. In `dist/src/runtime4.js`, `oa` gates relaunch teardown on that flag, and `$i` passes `terminateRunningApp` only for relaunch.
- `dist/apple/runner/AgentDeviceRunner/AgentDeviceRunnerUITests/RunnerTests+CommandDispatch.swift:498` checks the session app's foreground state before observe-only capture. Its `observeOnlyUnavailableResponse` at line 683 returns `OBSERVATION_UNAVAILABLE`. `RunnerTests+SnapshotExecution.swift:114` checks foreground state and process identity again after capture.
- `dist/src/client-types.d.ts:1099` defines the session app state result. After the screenshot, `command.appState` must return the same simulator and bundle, a live runner source, and `runningForeground`. Background states refuse with `foreign_app_foreground`. `RunnerTests+CommandDispatch.swift:54` reads `XCUIApplication.state` without activation, dispatched directly at line 454. This check is conservative when the runner reports background, but attempt 11 shows that it does not reliably detect the Settings handoff.
- `dist/src/runtime4.js`, `hs`, sends observe-only capture directly to the runner. The runner's observe-only branch precedes the usual presented-system-surface selection. Attempt 10 answered the notification alert with observe-only enabled. No alert-specific bypass or SDK patch was needed.

ADR 0066 also exists on the lower `ios/adr` branch. Its limit was amended here as authorized; this work does not modify that branch.

## Settings observations through the product

Attempts 12 and 13 replace the standalone diagnostic with the maintained proof's own product commands. Each Settings tap is followed by at most 40 observations without sleeps. The receipt records every call's UTC start and completion, duration, cumulative elapsed time, and result. Refusal is mandatory within the bound and must persist for three more product observations. Recovery must preserve the signed-in account, current screen, recording state during Teaching, and Session Simulator identity, then continue through account details and back.

Attempt 12 passed every combined criterion on iOS 26.5. Teaching's Settings tap succeeded; its first explicit observation refused after 1209 ms. In the later Run the tap returned fixture nodes, the first explicit observation returned another tree after 852 ms, and the second refused after 363 ms. The receipt's cumulative times include the tap and its pre-action observation work, not just the animation. The three persistence calls refused in each detour. Both recoveries continued on the same signed-in screen and simulator. The cleanup audit found no owned simulator, PID, port, record, fixture, or instance remaining, with the preexisting simulator set and states unchanged.

The returned trees expose semantic targets during the handoff. Input already refreshes observations before dispatch, but another foreground report during that window could still accept those targets. One extra post-action capture would not cover the two trees observed in attempt 12. The iOS Workspace now makes three sequential post-action captures, exposes only the last, and propagates any capture refusal immediately through the existing pause path, which clears retained observations. These are completed capture events, not sleeps or retries after a refusal. The regression supplies two trees followed by refusal and failed before the fix; it also verifies that only the last successful capture is returned and that an initial refusal is never retried. This mitigates the measured handoff, without claiming XCTest's foreground report is an infallible ownership signal.

Persistence is the product's retained paused refusal. These calls do not ask the SDK to inspect Settings again, and do not establish a timed SDK foreground guarantee. Attempt 12 evidence is `.cursor/skills/verify-contingency/artifacts/ios-0067-attempt12/`; launcher logs and cleanup audit are `/tmp/ios-0067-live/attempt12/`.

Attempt 13 passed the same complete receipt on the final implementation. Both Settings taps themselves returned `foreign_app_foreground`, so no handoff tree reached the proof caller. The first explicit observations refused after 56 ms and 12 ms respectively, and all six persistence observations refused. Return to Target App restored the signed-in account on the same Session Simulator in each case, Teaching continued with the original recording, and both journeys continued.
